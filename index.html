Firebase Signaling & ICE (STUN/TURN) Configuration

You can either edit the firebaseConfig and ICE_CONFIGURATION constants directly in index.html, or paste your Firebase project configuration JSON below for runtime signaling. When Firebase is unconfigured (using placeholder values), PulseMeet automatically falls back to browser-native BroadcastChannel signaling so you can test real WebRTC peer connections across multiple tabs on the same device.

Setup Guide, Firebase Security Rules & Testing Checklist

1. Concise Firebase Setup Guide

1. Create a Firebase project at console.firebase.google.com and enable Realtime Database and Authentication → Anonymous Sign-In.
2. Copy your Web App's firebaseConfig object into the clearly marked section in index.html (or paste it in the Signaling & ICE dialog).
3. Serve index.html over HTTPS or http://localhost (required by browsers for getUserMedia and getDisplayMedia).

2. Firebase Realtime Database Security Rules

Use the companion firebase-database.rules.json file supplied with this build. It requires Anonymous Authentication, restricts participant updates to the signed-in user, restricts host operations to the current host, and limits signalling reads to the intended recipient. Keep the database in Locked mode until those rules are published.

Important: Do not use public test-mode rules or a blanket authenticated write rule.

3. Browser Compatibility Limitations

• Screen Sharing (getDisplayMedia): Supported on desktop Chrome, Edge, Firefox, and Safari. Android and iOS mobile browsers generally do not support capturing the device screen from a web page.
• NAT Traversal (TURN): Public STUN servers work for most home/office networks, but symmetric NATs or strict corporate firewalls require configuring a TURN server.
• Mesh Scaling: Peer-to-peer mesh encodes/decodes streams per peer and is capped at 8 participants; larger rooms require an SFU.

4. Two-or-More Device Testing Checklist

• Create a meeting on Device A and copy the invitation link or Room ID.
• Join the Room ID on Device B and verify mutual live video & bidirectional audio.
• Toggle Microphone & Camera independently on each device and confirm badge updates.
• Test Voice-Only Mode, Screen Sharing (on desktop), Participant Sidebar, and Host End-for-All.
